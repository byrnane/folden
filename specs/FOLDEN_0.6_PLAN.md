# Folden 0.6 — Workspace UX

## Статус

Черновой план следующей продуктовой итерации.

## Цель версии

Довести существующий функционал Folden до состояния удобного ежедневного редактора.

Основной фокус версии:

- обновить визуальный стиль приложения;
- освободить максимум вертикального пространства под редактор;
- упростить навигацию между файлами и workspace;
- сделать вкладки и панели полноценными рабочими инструментами;
- добавить единый drag-and-drop для файлов, вкладок и панелей;
- добавить базовые пользовательские настройки;
- сохранить текущую модель из двух редакторских панелей без усложнения layout.

Версия не должна добавлять новые крупные подсистемы, не связанные напрямую с UX текущего редактора.

## 1. Новый application shell

### 1.1. Общая структура

Перестроить основной layout приложения:

```text
┌─────────────────────────────────────────────────────────────┐
│ Titlebar / App bar                                          │
├────┬──────────────────┬─────────────────────────────────────┤
│    │                  │ Shared document toolbar             │
│ A  │ Sidebar          ├──────────────────┬──────────────────┤
│ c  │                  │ Pane tabs        │ Pane tabs        │
│ t  │                  ├──────────────────┼──────────────────┤
│ i  │                  │                  │                  │
│ v  │                  │ Editor           │ Editor           │
│ i  │                  │                  │                  │
│ t  │                  │                  │                  │
│ y  │                  │                  │                  │
├────┴──────────────────┴──────────────────┴──────────────────┤
│ Status bar                                                  │
└─────────────────────────────────────────────────────────────┘
```

### 1.2. Основные изменения

- Убрать постоянные подписи `Main` и `Split`.
- Убрать отдельную панель инструментов из каждой редакторской панели.
- Добавить одну общую панель инструментов для активного документа.
- Убрать `Logs` и `Diagnostics` из основного интерфейса.
- Заменить постоянный diagnostics banner на toast-уведомление.
- Растянуть область редактора на всю доступную высоту.
- Сделать status bar максимально компактным.
- Визуально выделять активную редакторскую панель.

### 1.3. Общая панель инструментов

Общая toolbar управляет документом в активной панели.

Она должна:

- показывать текущий режим `Visual / Source`;
- показывать инструменты форматирования только для Visual-режима;
- обновляться при переключении активной панели или вкладки;
- не влиять на документ во второй панели;
- скрывать недоступные действия для plain text;
- занимать одну строку по высоте.

Пример состава:

```text
Visual | Source    H1 H2  B I S  Code  Lists  Quote  Link  Image  HR
```

Обычные операции `Save`, `Undo`, `Redo` не обязаны постоянно занимать место в toolbar, если они доступны через shortcuts и меню приложения.

## 3. Activity bar и sidebar

### 3.1. Activity bar

Добавить слева узкую вертикальную панель фиксированной ширины.

Разделы версии 0.6:

- Workspace;
- Settings.

Settings размещается в нижней части activity bar.

Home не обязан быть отдельным разделом. Стартовый экран может открываться автоматически, когда workspace не выбран.

### 3.2. Workspace sidebar

Структура:

```text
OPEN EDITORS
  test.md
  notes.md
  article.md

FILES
  workspace 1
  workspace 2
  ...
```

#### Open Editors

- Показывать все открытые документы.
- Показывать dirty-state.
- Показывать, в какой панели открыт файл.
- Активировать документ по клику.
- Закрывать документ.
- Поддерживать контекстное меню.
- Поддерживать drag-and-drop.
- Позволять свернуть секцию.

#### Files

- Сохранить дерево workspace.
- Добавить контекстные меню.
- Поддержать drag-and-drop файлов в панели редактора.
- Отображать loading и error states отдельных директорий.

### 3.3. Стартовый экран

При отсутствии workspace показывать:

- `Open File`;
- `Open Workspace`;
- список последних workspace;
- список последних файлов, если он будет добавлен;
- состояние восстановления прошлой сессии, если оно требуется.

Для recent workspaces:

- быстрое открытие;
- удаление из истории;
- полный путь в tooltip;
- обработка удалённых или перемещённых директорий.

## 4. Изменяемые размеры областей

Пользователь должен иметь возможность менять:

- ширину основного sidebar;
- соотношение ширины левой и правой редакторских панелей.

### Требования

- Минимальная ширина sidebar.
- Минимальная ширина редакторской панели.
- Сохранение размеров между запусками.
- Двойной клик по splitter сбрасывает размер.
- Sidebar можно свернуть.
- Размеры корректно пересчитываются после изменения окна.
- CodeMirror и Tiptap корректно обновляют layout.
- Splitter имеет понятный hover-state и удобную область захвата.
- Добавить `Reset layout` в настройки.

В версии 0.6 поддерживаются только две горизонтально расположенные редакторские панели.

## 5. Вкладки

### 5.1. Базовое поведение

- Изменение порядка вкладок через drag-and-drop.
- Перенос вкладки между панелями.
- Закрытие средней кнопкой мыши.
- Закрытие через кнопку на вкладке.
- Dirty-state.
- Tooltip с полным путём.
- Автоматическая прокрутка к активной вкладке.
- Корректное поведение при переполнении.
- Отображение родительской папки для файлов с одинаковыми именами.

### 5.2. Контекстное меню вкладки

- `Close`;
- `Close Others`;
- `Close Tabs to the Right`;
- `Move to Other Pane`;
- `Reveal in Explorer`;
- `Copy Full Path`;
- `Copy Relative Path`.

### 5.3. Поведение панелей

- Если второй панели нет, перенос вкладки к правой drop-zone создаёт её.
- Если в правой панели закрыта последняя вкладка, split автоматически убирается.
- Один документ может быть открыт в обеих панелях.
- Source и Visual могут использоваться одновременно для одного документа.
- Активная панель всегда должна быть однозначно определена.
- После закрытия активной вкладки фокус переходит на предсказуемую соседнюю вкладку.

## 6. Единая система drag-and-drop

Реализовать единый DnD-контракт для всех основных сценариев.

### 6.1. Drag sources

- внешний файл из Windows Explorer;
- внешняя папка;
- файл из дерева workspace;
- вкладка;
- документ из Open Editors.

### 6.2. Drop targets

- левая редакторская панель;
- правая редакторская панель;
- позиция между вкладками;
- пустая область редактора;
- зона создания второй панели;
- стартовый экран.

### 6.3. Поведение

- Внешний файл открывается без копирования.
- Внешняя папка открывается как workspace.
- Workspace-файл открывается в выбранной панели.
- Вкладка перемещается, а не дублируется.
- Drop-zone показывается до отпускания мыши.
- Недопустимые области не подсвечиваются.
- `Esc` отменяет drag.
- После drop корректно восстанавливается фокус.
- Все drag payload должны иметь единый типизированный формат.

Отдельная кнопка `Open Right` после реализации DnD удаляется.

- удобная клавиатурная навигация по основным областям.

### Focus mode

Focus mode скрывает:

- activity bar;
- sidebar;
- status bar;
- необязательные элементы app bar.

При этом вкладки и общая toolbar остаются доступны.

Command Palette в scope версии не входит.

## 12. Техническая организация

### 12.1. Layout state

Определить отдельное состояние интерфейса:

- активный activity section;
- видимость sidebar;
- ширина sidebar;
- split ratio;
- видимость status bar;
- focus mode;
- UI scale;
- density.

Layout state не должен смешиваться с состоянием документов и workspace.

### 12.2. DnD state

Выделить отдельный UI/controller слой для:

- текущего drag payload;
- активной drop-zone;
- reorder preview;
- отмены операции;
- применения результата drop.

Доменные операции с документами и workspace должны вызываться через существующие workflows.

### 12.3. Настройки

Настройки должны разделяться на:

- persisted settings;
- временное UI-state;
- session layout.

Не все параметры layout обязаны быть глобальными пользовательскими настройками.

### 12.4. Ограничения архитектуры

- Не переносить workflow-логику в Vue-компоненты.
- Не обращаться к Tauri API напрямую из UI.
- Не раздувать `applicationShell` новой логикой.
- Не смешивать DnD presentation state с доменным состоянием документа.
- Не обходить существующий save/recovery flow.
- Не добавлять произвольную split-grid модель в 0.6.

## 15. Definition of Done

Folden 0.6 считается готовым, когда пользователь может:

1. Открыть workspace через диалог или drag-and-drop папки.
2. Открыть несколько файлов.
3. Менять порядок вкладок.
4. Переносить вкладки между двумя панелями.
5. Создавать вторую панель через drag-and-drop.
6. Закрывать вкладки средней кнопкой мыши.
7. Менять ширину sidebar и редакторских панелей.
8. Управлять активным документом через одну общую toolbar.
9. Быстро переключаться между последними workspace.
10. Видеть все открытые документы в Open Editors.
11. Настроить шрифты, размеры текста и Autosave.
12. Перезапустить Folden с восстановленным layout.
13. Работать без потери фокуса и неожиданных переключений активной панели.
14. Использовать редактор при маленьком размере окна и высоком DPI.
15. Понимать состояния сохранения, конфликта и отсутствующего файла без обращения к логам.

## Итог

Folden 0.6 должен превратить уже работающий редактор в цельный продукт:

- интерфейс становится компактнее;
- документ получает максимум пространства;
- вкладки и панели работают предсказуемо;
- drag-and-drop покрывает основные сценарии;
- workspace удобно открывать и переключать;
- приложение сохраняет пользовательский layout;
- базовые настройки делают редактор пригодным для ежедневной работы.
