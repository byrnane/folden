# Архитектура Folden

[English](ARCHITECTURE.md) · [Разработка](DEVELOPMENT.ru.md)

Руководство описывает текущий код и назначение основных частей приложения.

## Направление зависимостей

```text
Интерфейс Vue
  ↓
applicationShell и контроллеры
  ↓
контракты нативных возможностей
  ↓
адаптеры Tauri
  ↓
команды Rust
  ↓
файловая система и операционная система
```

Оболочка связывает эти части и предоставляет интерфейсу состояние и действия. Чистые правила документов и Markdown находятся в `domain`; их используют остальные слои.

## Слои интерфейса

### `src/ui`

Представления Vue, редакторы, диалоги и навигация. Компоненты отображают состояние и вызывают API приложения. Адаптеры редакторов работают с Tiptap и CodeMirror. Общие компоненты оглавления и карты документа находятся в `navigation/`; карта рисуется на canvas. Код исходного и визуального редакторов загружается по требованию.

### `src/application`

Контроллеры координируют редактирование, операции с файлами, настройки и жизненный цикл приложения. `applicationShell.ts` создаёт их, передаёт зависимости и возвращает публичный API из `useApplicationShell`. Контроллеры получают нативные возможности через `ports/nativePorts.ts`.

`settings/` задаёт значения по умолчанию, ограничения и нормализацию. `i18n.ts` переводит английские ключи интерфейса; `systemLanguage.ts` определяет исходный язык. Выбранный язык сохраняется в настройках приложения.

### `src/domain`

Независимые от фреймворков правила и типы TypeScript: ревизии документов, общая история, очереди сохранения, синхронизация редакторов, блоки Markdown, изображения, ссылки, диапазоны поиска, навигация, конфликты и контракты нативных данных. Слой не зависит от Vue, Tauri, компонентов интерфейса, браузерного хранилища или инфраструктуры.

Блочная модель Markdown сохраняет неизменённые участки исходника и стабильные ID блоков. Визуальный редактор оставляет неподдерживаемый синтаксис в редактируемых исходных блоках. Общая история отмены и повтора хранит текстовые изменения.

### `src/infrastructure`

`tauri/` реализует нативные контракты и предпросмотр локальных изображений через протокол ресурсов. `settings/settings.ts` читает и записывает браузерное хранилище, включая перенос старых настроек раскладки. Контроллеры приложения используют эти реализации через контракты.

## Владение состоянием

Каждый контроллер хранит своё состояние и предоставляет методы для его изменения. Оболочка возвращает интерфейсу нужные реактивные ссылки и вычисляемые значения.

| Контроллер                                          | Назначение                                                                                                           |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `documentController`                                | Открытые документы, ревизии, несохранённые изменения, содержимое, состояния сохранения и внешних файлов              |
| `paneController`                                    | Панели, вкладки, активная панель, состояние представлений и режим документа в каждой панели                          |
| `workspaceController`                               | Дерево проекта, загруженные ветки, выделение, недавние папки и обновление путей                                      |
| `sessionController`                                 | Снимки сессии и восстановления, ожидающие записи и отложенное сохранение                                             |
| `externalChangesController`                         | Обработка файловых событий, предупреждения наблюдателя и отложенное обновление документов/дерева                     |
| `visualSafetyController`                            | Безопасность визуального режима и разрешение сетевых изображений для каждого документа                               |
| `dialogController`                                  | Ввод, подтверждение, несохранённые изменения, безопасность, конфликты и восстановление                               |
| `commandController`, `applicationCommandController` | Регистрация и выполнение команд                                                                                      |
| `layoutController`                                  | Размеры, видимость, сброс и сохранение раскладки                                                                     |
| `documentAnalysisController`                        | Запросы фонового анализа оглавления, карты и числа слов; устаревшие результаты отбрасываются                         |
| `searchController`                                  | Поиск по проекту, быстрое открытие, отмена запросов и события результатов                                            |
| `documentWorkflowController`                        | Открытие, сохранение, закрытие, автосохранение, перезагрузка, конфликты, получение текста редактора, отмена и повтор |
| `workspaceWorkflowController`                       | Открытие/восстановление проекта, загрузка дерева, создание, переименование, корзина и обновление веток               |
| `documentFeaturesController`                        | Поиск/замена, шаблоны, импорт изображений, ссылки/история, печать и перенос; создаёт и освобождает поиск             |
| `applicationLifecycleController`                    | Восстановление при запуске, диалоги восстановления, нативные подписки и закрытие окна                                |

Фоновый анализ выполняется в Web Worker из `src/workers`. Настройки нормализуются в слое приложения и сохраняются инфраструктурой.

## Нативные контракты

Контракты определены в `src/application/ports/nativePorts.ts`, реализации находятся в `src/infrastructure/tauri`.

| Контракт             | Возможности                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DocumentFilePort`   | Открытие/сохранение текста, закрытие нативных дескрипторов документов и импорт изображений                                                                   |
| `WorkspaceFilePort`  | Открытие/восстановление проекта, просмотр каталогов, скрытые пути и область наблюдения, создание/переименование/перенос/корзина, список файлов, поиск/отмена |
| `SessionStoragePort` | Загрузка/сохранение сессий и снимков восстановления                                                                                                          |
| `DiagnosticsPort`    | Локальные журналы, открытие их папки и экспорт диагностики                                                                                                   |
| `NativeEventPort`    | Подписки на события, обработка закрытия и уничтожение нативного окна                                                                                         |

Для новой нативной возможности расширьте подходящий контракт и реализуйте адаптер. Передайте контракт контроллеру. Прямые импорты Tauri оставляйте в инфраструктуре.

## Нативный слой Rust

Модули находятся в `src-tauri/src/native`. `lib.rs` регистрирует команды, создаёт состояние, настраивает журналы и обработчик паники.

| Модуль           | Назначение                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `types.rs`       | Сериализуемые данные, общие с TypeScript                                                                 |
| `errors.rs`      | Коды ошибок, возможность повтора, пользовательские сообщения и диагностика                               |
| `state.rs`       | Разрешённые документы/проекты, состояние наблюдения и поиска                                             |
| `paths.rs`       | Нормализация и проверка путей, границы проекта                                                           |
| `watcher.rs`     | Наблюдение за загруженными каталогами и открытыми документами; фильтрация событий и временных сохранений |
| `documents.rs`   | Декодирование текста, определение формата, атомарное сохранение и проверка внешних изменений             |
| `workspace.rs`   | Разрешение доступа к проекту, просмотр каталогов, ограниченный обход и файловые операции                 |
| `search.rs`      | Отменяемые поиск и список файлов, ограничения, позиции текста и пакеты результатов                       |
| `images.rs`      | Проверка изображений, импорт в ресурсы документа и доступ к предпросмотру                                |
| `persistence.rs` | Хранение сессии и данных восстановления                                                                  |
| `diagnostics.rs` | Локальные журналы и экспорт с удалением чувствительных значений                                          |

## Основные потоки данных

### Открытие документа

Интерфейс вызывает оболочку, а `documentWorkflowController` запрашивает файл через `DocumentFilePort`. Rust проверяет доступ и возвращает содержимое, путь, формат и отпечаток файла. Контроллер документов записывает эти данные, контроллер панелей открывает представление. Планируется сохранение сессии.

### Редактирование документа

Исходный или визуальный редактор сообщает об изменении текста. Контроллер документов обновляет ревизию и общую историю, затем синхронизируются видимые представления того же документа. При необходимости планируются автосохранение и запись данных восстановления.

### Сохранение и автосохранение

Контроллер получает актуальный текст редактора и использует очередь сохранения. Нативный контракт получает содержимое, формат и ожидаемый отпечаток файла. Rust отклоняет запись изменившегося файла и сохраняет атомарно, сохраняя BOM и переводы строк. Контроллер отмечает сохранённую ревизию либо явную ошибку/конфликт. Сохранение по новому пути обновляет затронутую ветку проекта.

### Переключение Source и Visual

Оболочка проверяет поддержку Markdown и безопасность визуального режима. Перед сменой режима панели она получает актуальный текст и запоминает выделение/прокрутку. Неподдерживаемый синтаксис остаётся в исходных блоках; сетевые изображения используют разрешение документа.

### Обновление настроек и раскладки

Представление настроек изменяет состояние, предоставленное оболочкой. Правила приложения нормализуют значения; инфраструктура сохраняет их и переносит старые значения раскладки при загрузке.

### Открытие и обновление рабочего пространства

Rust разрешает доступ к выбранному корню. Контроллер проекта хранит дерево; содержимое каталогов загружается по мере необходимости. Файловые операции обновляют открытые пути и затронутые ветки. Область наблюдения состоит из загруженных каталогов и открытых документов.

### Событие файлового наблюдателя

Контроллер жизненного цикла получает нативные файловые события и передаёт их в `externalChangesController`. Тот отмечает отсутствующие файлы и конфликты, планирует перезагрузку документов и обновляет затронутые ветки.

### Поиск по проекту и быстрое открытие

Поиск получает актуальный текст видимых редакторов и учитывает несохранённое содержимое открытых документов. Их пути исключаются из нативного обхода. Rust обходит разрешённый корень с учётом игнорируемых имён и скрытых путей, отправляет `folden://workspace-search-batch` с ID проекта/запроса. Контроллер отбрасывает старые результаты и отменяет заменённые запросы.

Нативный обход останавливается на 100 000 элементах или 32 уровнях вложенности и пропускает символические ссылки. Поиск читает файлы до 2 МиБ и возвращает до 5000 совпадений. Быстрое открытие показывает до 100 ранжированных кандидатов. Неполные результаты и пропущенные файлы обозначаются в интерфейсе. Выбор результата поиска открывает его диапазон текста в исходном режиме.

### Изображения, ссылки на документы и печать

- Импорт изображения сначала сохраняет новый черновик. Rust проверяет изображение, записывает его в папку ресурсов документа и возвращает относительную ссылку. Локальный предпросмотр требует разрешённого доступа; сетевые изображения — разрешения для документа.
- Относительные ссылки на документы разрешаются доменной функцией. Контроллер дополнительных действий открывает файл и указанный якорь заголовка, хранит историю переходов текущего проекта.
- Подготовка печати получает актуальный текст и фиксирует содержимое и разрешение изображений. `PrintView.vue` показывает этот снимок и вызывает системный диалог. Приложение не может подтвердить сохранение PDF или печать страницы.
- Перенос Markdown захватывает соседнюю папку `<stem>.assets`. Совпадение имён в месте назначения блокирует перенос. Если перенос ресурсов завершился ошибкой, Rust пытается вернуть документ. Ссылки внутри документов остаются прежними и требуют проверки после переноса.

### Внешний конфликт

Сохранение или файловое событие обнаруживает внешнее изменение. Диалог предлагает версию с диска, версию Folden, отдельную копию или объединённый результат. Контроллер применяет выбор, сохраняя несохранённый текст.

### Сохранение сессии

Оболочка наблюдает за проектом, панелями, режимами, метаданными документов и записями восстановления. Контроллер сессии откладывает и последовательно выполняет запись через `SessionStoragePort`. Записи сессии содержат пути, имена, раскладку панелей и режимы. Черновики и изменённые файлы создают снимки восстановления с текстом, форматом и отпечатком файла на диске. Все активные документы с изменениями сохраняются. Ожидающие записи ограничиваются отдельно до 64 после удаления дубликатов.

### Восстановление после сбоя

При запуске приложение загружает сессию и снимки восстановления, восстанавливает доступные файлы/раскладку и спрашивает, какие записи восстановить или удалить. Затем сохраняет открытые документы и обновлённое состояние восстановления.

### Закрытие приложения

Контроллер жизненного цикла обрабатывает запрос закрытия и спрашивает о несохранённых изменениях. Он дожидается финальной записи сессии/восстановления и уничтожает окно после завершения работы. Ошибка записи оставляет окно открытым и показывает сообщение. Нативные дескрипторы освобождаются при закрытии документов; оставшееся нативное состояние завершается вместе с процессом приложения.

## Добавление функции

1. Найдите компонент, контроллер или доменное правило, отвечающее за поведение.
2. Расширьте его состояние/действия. Для доступа к ОС используйте нативный контракт.
3. Подключите действие через оболочку и нужный компонент интерфейса.
4. Обновите TypeScript/Rust-тесты контрактов при изменении нативных данных или команд.
5. Проверьте поведение на том уровне, где оно реализовано.

## Сохранность документов

Сохраняйте неизменённый текст, неподдерживаемый Markdown, BOM и переводы строк. Записывайте файлы через очередь сохранения с проверкой ожидаемого отпечатка. Основная копия сохранённого документа находится в его файле; сессия и данные восстановления помогают вернуть работу. Показывайте ошибки и сохраняйте единственную несохранённую копию при перезагрузке, разрешении конфликта и закрытии.

## Карта тестирования

| Изменение                                                | Проверки                                                          |
| -------------------------------------------------------- | ----------------------------------------------------------------- |
| Правило документа, Markdown или проекта                  | Доменные модульные тесты                                          |
| Контроллер или сценарий                                  | Модульные тесты с подставными нативными контрактами               |
| Контракт нативных данных/команды                         | Тесты контрактов TypeScript/Rust                                  |
| Пути, файловые операции или хранение в Rust              | Тесты модуля Rust                                                 |
| Редактирование или работа с проектом                     | Целевые модульные тесты и Playwright E2E                          |
| Сохранение, восстановление, наблюдение или закрытие окна | Подходящие модульные/Rust-тесты и проверка настольного приложения |

Тесты находятся в `tests/unit`, `tests/contracts` и `tests/e2e`. Большие документы и проекты проходят отдельные проверки производительности. Команды перечислены в [Разработке](DEVELOPMENT.ru.md); проверки на реальных ОС записаны в [статусе беты](BETA-0.12.0.ru.md).

## Жизненный цикл и очистка

Контроллеры с таймерами, подписками или фоновыми задачами предоставляют `dispose`. У каждой подписки один владелец. Если асинхронная регистрация завершилась после освобождения контроллера, новый обработчик сразу удаляется. При размонтировании оболочка освобождает контроллеры дополнительных действий, раскладки, жизненного цикла и анализа; очистка жизненного цикла также завершает работу документов, сессии и внешних изменений.
