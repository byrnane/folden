# Подготовка релиза

[English](RELEASE.md) · [Разработка](DEVELOPMENT.ru.md)

Бета 0.12.0 опубликована. Результаты находятся в [статусе проверок](BETA-0.12.0.ru.md). Руководство описывает подготовку следующих бета-выпусков. Публикация, создание тегов и замена установленного приложения требуют разрешения владельца.

## Пакеты

| Платформа           | Целевая платформа Rust   | Среда CI         | Пакет       |
| ------------------- | ------------------------ | ---------------- | ----------- |
| Windows x64         | `x86_64-pc-windows-msvc` | `windows-2022`   | NSIS `.exe` |
| macOS Intel         | `x86_64-apple-darwin`    | `macos-15-intel` | `.dmg`      |
| macOS Apple Silicon | `aarch64-apple-darwin`   | `macos-15`       | `.dmg`      |

Windows требует WebView2; установщик может скачать среду Microsoft. Пакеты macOS требуют версию 14 и новее. Windows-пакеты не подписаны, пакеты macOS имеют ad-hoc подпись без нотариального заверения Apple. Проверяйте установку и первый запуск с учётом этих ограничений ОС.

Для Linux в этой бете нет официального пакета и записи о проверках на реальной ОС. Разрешённая [самостоятельная сборка на Linux](DEVELOPMENT.ru.md#самостоятельная-сборка-на-linux) и уведомления о зависимостях доступны по [LICENSE.md](../LICENSE.md).

## Проверки

Используйте [инструкцию разработки](DEVELOPMENT.ru.md) и закреплённые в ней версии Node/Rust. Из корня репозитория:

```text
npm ci
npm run quality
npm run test:release
npm run privacy:check
npm run licenses:generate
npm run licenses:check
npm run test:coverage
npx playwright install chromium
npm run test:e2e
npm run test:performance
```

Проверки нативного кода запускаются из `src-tauri`:

```text
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

Собирайте и проверяйте каждый пакет на соответствующей ОС. Для Windows:

```text
npm run release:build -- --target x86_64-pc-windows-msvc
npm run release:verify -- --target x86_64-pc-windows-msvc
```

Для каждой сборки macOS используйте целевую платформу из таблицы. Проверка распаковывает финальный пакет, сверяет версию, архитектуру, лицензии и личные данные, готовит файлы в `build/release/<target>/` вместе с `SHA256SUMS.txt`. Карты исходников, дампы, журналы, личные пути и старые тестовые установщики блокируют проверку.

Каждый пакет содержит `LICENSE.md` и сгенерированный `THIRD_PARTY_NOTICES.md`. Файлы Windows-выпуска также содержат `nsis-3.11-src.tar.bz2` — неизменённые исходники NSIS 3.11, обязательные по его лицензии. Закреплённый SHA-256 входит в файл контрольных сумм. Генератор уведомлений и кеш лицензий описаны в [Разработке](DEVELOPMENT.ru.md). Проверки Linux-пакетов остаются в скриптах для поддержки кода; сами пакеты не входят в официальную бету.

## Кандидат и черновик

CI запускается для `master`, `main` и запросов на слияние. Отправка ветки `release/beta-*` запускает проверки пакетов и сохраняет три архива с именами `folden-<target>`. Срок хранения — 14 дней. Изучите результаты и проверьте пакеты кандидата перед подготовкой черновика.

Для следующей версии используйте `npm run version:bump -- <version>`, заполните журнал изменений и `docs/releases/v<version>.md`. После согласования создайте и отправьте новый тег `v<version>` на проверенном коммите. Тег должен совпадать с версией в `package.json`; существующие опубликованные теги и выпуски остаются неизменными.

Выберите способ создания черновика:

1. **Собрать из тега.** Запустите **Draft beta release**, указав один тег как ссылку запуска и значение `tag`. Установите `create_draft=true`, чтобы после проверок создать черновик бета-выпуска; по умолчанию значение false. Запуск собирает новые пакеты, поэтому перед публикацией проверьте финальные файлы черновика на реальных ОС.
2. **Сохранить проверенные пакеты кандидата.** Скачайте три архива точного запуска в `build/release/folden-<target>/` чистой рабочей копии проверенного коммита. Задайте `RELEASE_TAG` равным согласованному тегу, а `RELEASE_COMMIT` — полному SHA проверенного коммита. Выполните `node scripts/release-draft.mjs`. Скрипт сверяет имена файлов, контрольные суммы, лицензии, чистоту рабочей копии и коммит удалённого тега. Он копирует проверенные файлы без пересборки и создаёт черновик бета-выпуска.

Для запуска через CLI замените `<tag>` согласованным тегом версии:

```text
gh workflow run release.yml --ref <tag> -f tag=<tag> -F create_draft=true
```

Настройте окружение `release-draft`: обязательное подтверждение владельца и разрешённые теги версий. Правило проверяет `GITHUB_REF` запуска; используйте тег как ссылку запуска. Право записи в репозиторий получает только задача создания черновика. Скрипт отказывается заменять существующий выпуск. Настройка описана в [руководстве репозитория](../.github/REPOSITORY_SETUP.md).

## Проверки на реальных ОС и публикация

Проверьте финальный Windows-пакет и оба пакета macOS. Запишите контрольную сумму пакета, версию ОС, процессор и результаты:

- первый запуск, выбор RU/EN, сохранение и повторное открытие;
- восстановление после принудительного закрытия, внешние изменения и конфликты;
- локальные изображения, относительные ссылки и перенос файлов/папок;
- буфер обмена, файловые диалоги, печать и сохранение PDF;
- установка, обновление и удаление, включая UAC, Program Files и прежнюю установку Windows в нестандартном пути.

Проверьте в черновике три пакета, общий `SHA256SUMS.txt`, лицензии, обязательный архив исходников NSIS и примечания к выпуску. Публикуйте только файлы, прошедшие проверки на реальных ОС. Запишите результаты и оставшиеся пробелы в документе проверок этой версии по примеру [BETA-0.12.0.ru.md](BETA-0.12.0.ru.md). Браузерные тесты проверяют сценарии с подставными нативными API; системные диалоги и установщики требуют этих настольных проверок.
